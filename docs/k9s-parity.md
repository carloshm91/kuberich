# K9s capability audit

Reviewed 2026-10-04. Reference: [K9s v0.51.0](https://github.com/derailed/k9s/releases/tag/v0.51.0),
commit `558caafe7ba067467de46b320cc22ef11fef9c34`.

**Complete product capability rows remain planned.** Local CLI/configuration,
the terminal preview, F04 security helpers, F05 launch checkpoint, C01 sessions,
C02 resource reads, C03 synchronization and C04 active-view ownership
have implementation evidence, but do not establish a complete capability family's
K9s parity.

The goal is complete functional coverage of the public reference, with every
discovered capability assigned to implementation and verification work. A source
inventory and a ticket are evidence of planning, not proof that a feature works.

## Audit method and limits

The review covers launch commands, README workflows, view/action registrations,
resource adapters, configuration schemas, plugin contracts and bundled plugin
files. The [source census](k9s-source-inventory.json) records 411 source/schema/plugin/example
files and 798 extracted identifiers with task owners. Extraction is heuristic:
it helps detect omissions but cannot prove runtime or semantic equivalence.
The [machine-readable capability map](capabilities.json) is checked in CI.

The delta to master commit `7064f96f1e852e71efcb848a483a5b6d4b986f35`
contains 103 commits and 129 changed files; the census indexes those changes and
records relevant CLI/UI/configuration differences separately from released behavior.
Q06 refreshes this audit and requires test evidence before a stable parity claim.

## Historical paid offering

The [official v0.24.7 announcement](https://github.com/derailed/k9s/releases/tag/v0.24.7)
establishes the existence of K9sAlpha and additional features. On the review date,
the linked official site did not yield an accessible complete feature catalog.
Its current commercial status and full additional feature set remain unverified.
Q07 tracks that evidence gap. We cannot claim 100% Alpha parity from its existence
alone. Any substantiated capability will receive an open-source implementation
ticket; no proprietary source, assets or private access is required by this plan.

Kubetrol has no paid capability tiers. External services invoked by optional
plugins retain their own terms and infrastructure costs. They are not mandatory
dependencies of the product.

## Completion rules

A capability becomes implemented only after its issue acceptance criteria pass.
It becomes verified after applicable real API/terminal/installed-artifact checks
are linked. Count planned, implemented, verified, intentional differences and
unresolved evidence gaps separately. No single aggregate percentage may conceal
an unknown paid feature, an unsupported platform or a failing installation.

Known deliberate differences include confirmations for force-delete, local opt-in
for annotation-triggered listeners, conservative read-only handling of shell/plugins,
original branding and explicit configuration import. Functional alternatives and
security differences must be documented, not described as byte-for-byte compatibility.
