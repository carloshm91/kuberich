## Selected shell, scope and failure behavior

Pod `x`/`:shell`/`:exec` opens container selection; container `s`/`x` launches the
configured shell. Enter on a pod still opens containers and Enter on a container
still opens logs. The default shell is `sh`; YAML `shell` accepts a bounded literal
argument list. No shell-string interpolation or automatic exec retry occurs.

Unit, loopback API and Pilot cases verify captured context/namespace/pod UID/name,
container, environment, cwd and configured argv; replacement/deletion, completed
or deleting pods, stale scope and delayed preparation cannot silently retarget.
Read-only policy runs before preparation/tool lookup. The private delegated
connection snapshots the prepared endpoint/TLS/auth mechanism; it has mode 0600
inside the owned 0700 directory and is removed on return/failure/cancellation.
The caller's kubeconfig and current-context are not rewritten.

Repeated cancellation drains owned file workers, process startup and terminal
handoff. Unexpected shell-worker faults reach the existing sanitized application
error hook after staged connection cleanup; the regression verifies no unobserved
task exception and closes the owned client. Expected failures stay in the retained
container view with safe, scrollable feedback, including at 40×12. Missing kubectl,
missing image executable, denied reads and unavailable targets have actionable
messages. Shell argv and raw kubectl output do not enter retained diagnostics.

Native source and fresh-wheel PTYs exercise actual typed input, resize, Ctrl+C,
fullscreen use and repeated return. Scenarios also cover failed exec, missing local
kubectl, missing image shell, read-only refusal, deleted pods and parent SIGTERM.
The launch path preserves exit 143 after SIGTERM cleanup rather than mapping it
to a generic exit 1. Container/pod cursor and viewport remain retained on return.

## Actual Kubernetes qualification

The required script creates and deletes only its own random `kubetrol-test-`
cluster, namespace, two-container pod and limited-RBAC service account. It never
falls back to the user's kubeconfig or active context. The final trial uses kind
0.33.0, Kubernetes/kubectl 1.36.4 and node/Alpine images pinned by digest. The matching
kubectl binary is downloaded into a temporary tool directory and SHA-256 verified;
no global kubectl is replaced.

Four actual CLI trials pass: default shell, configured `/bin/sh -i`, unavailable
image shell and a real pods/exec RBAC denial. The success case selects `app-b`,
types and reads remote values, checks remote `stty` after resize, edits/reads a
file through BusyBox vi, resizes while vi owns the screen, interrupts a remote
sleep with Ctrl+C and returns repeatedly. Changing only the fixture's source
kubeconfig endpoint after connection does not retarget the prepared shell session.
All four PTYs restore the terminal exactly. The owned cluster is deleted before
the verification command exits successfully.

## Reproduce and retained evidence

Run the [locked quality commands](../quality.md) in separate environments with
explicit CPython 3.12.12, 3.13.12 and 3.14.3. The behavioral command is:

```sh
uv run --locked --python 3.12.12 pytest --cov=kubetrol --cov-branch --cov-report=term-missing --cov-report=xml --cov-report=json
```

Repeat with the other interpreters, then apply coverage/diff gates and build/
metadata checks. After merge, changed-line evidence compares against pre-merge
base `db4edbe333c1eb6913b239f52853723852a84cae`, rather than updated main.
For actual Kubernetes qualification with the verified tools:

```sh
uv run --locked --python 3.12 python -m scripts.verify_shell_kind --kind /path/to/kind --kubectl /path/to/kubectl
```

The [current maintainer trial](../first-preview.md#selected-container-shell-s04-32--current-trial)
requires only an interactive terminal, kubectl and an already trusted kubeconfig.

Evidence is archived at `/tmp/kubetrol-32-evidence`: summary.json, per-interpreter
coverage/diff reports, validation logs, candidate distributions, SVGs, native PTY
transcripts/restoration summaries and the sanitized real-cluster trial. Temporary
artifacts can be regenerated. Earlier qualification is retained separately.
Initial full suites exposed buffered stdout reentrancy when SIGWINCH interrupted
a fixture's readiness print. A forced signal-during-write reproduction established
the cause; the owned fixture signal handlers now use `os.write`. The forced
reproduction and focused terminal/installed cases then pass. Final results above
come from complete suites on the same frozen trees, with no skipped failures or
coverage exclusions. The real-cluster PTY sequences also wait for actual modal,
shell and vi state transitions before sending dependent keystrokes.
