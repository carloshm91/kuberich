# KubeRich 0.2.0

## Features

This release makes KubeRich configurable and extensible. Preview and save
built-in or custom themes, globally or per context. Configure navigation keys,
command aliases and resource columns. Invalid settings fall back to working
defaults ([#56](https://github.com/carloshm91/kuberich/issues/56),
[#57](https://github.com/carloshm91/kuberich/issues/57)).

Run local plugins that you configure explicitly. Each plugin shows a review form
before it runs and supports captured, background and full-terminal modes. A
census documents compatibility with common K9s plugin files
([#58](https://github.com/carloshm91/kuberich/issues/58),
[#59](https://github.com/carloshm91/kuberich/issues/59),
[#60](https://github.com/carloshm91/kuberich/issues/60)).

Inspect ConfigMap and Secret keys with values hidden by default. Reveal or copy a
value on request, and edit Secrets through a private draft, a redacted review and
a separate dry-run and apply ([#55](https://github.com/carloshm91/kuberich/issues/55)).

Recall commands and filters, use inverse and fuzzy filters, mark favorite
namespaces and copy names or text to the clipboard. Mouse reporting is opt-in
([#61](https://github.com/carloshm91/kuberich/issues/61)). Port forwarding adds
named mappings, presets and reconnects
([#62](https://github.com/carloshm91/kuberich/issues/62)).

Rename or delete a kubeconfig context after a review, with a backup, and clean up
completed and failed pods with `:cleanup`
([#63](https://github.com/carloshm91/kuberich/issues/63)).

Define jumps from a selected row to a related view and run them with `:jump`.
KubeRich reloads the preference file while it runs and keeps the last valid
preferences when the file is invalid. Set `read_only` and `refresh_seconds` per
context. Themes can use the terminal background as a palette color, views show
full API titles, and KubeRich reports unknown preference fields
([#64](https://github.com/carloshm91/kuberich/issues/64)).

Homebrew installs a prebuilt bottle on macOS Apple Silicon, macOS Intel and Linux
x86_64 ([#193](https://github.com/carloshm91/kuberich/issues/193)).

## Fixes

Table caches release old entries when views change, and configuration key
columns are sized from their data
([#62](https://github.com/carloshm91/kuberich/issues/62)).
Preference migration keeps plugin file locations and working directories.
Revisiting a theme reuses its parsed style
([#58](https://github.com/carloshm91/kuberich/issues/58)).

The locked aiohttp and certifi dependencies are updated for published security
advisories.

## Compatibility and migrations

Supported Python versions remain CPython 3.12 to 3.14 on Linux and macOS.
Existing 0.1.0 preferences load without changes. New settings are optional, and
KubeRich never rewrites your preferences or kubeconfig unless you save a change
or confirm a context rename or delete.

## Installation

Version 0.2.0 is available from PyPI, the project Homebrew tap and
[GitHub Releases](https://github.com/carloshm91/kuberich/releases/tag/v0.2.0):

```sh
uv tool install --python 3.12 kuberich
# Alternative:
pipx install --python python3.12 kuberich
# Project organization tap:
brew install kuberich/tap/kuberich
```

GitHub Release assets include the four platform archives, `DOWNLOAD-SHA256SUMS`,
audit and provenance records and these notes. Homebrew pours a bottle on macOS 14
or newer (Apple Silicon), macOS 15 or newer (Intel) and Linux x86_64. Other
systems build from source.

See the [installation guide](../installation.md).

## Upgrade and uninstall

Upgrade from 0.1.0 with `uv tool upgrade kuberich`, `pipx upgrade kuberich` or
`brew upgrade kuberich/tap/kuberich`. Upgrade trials start from the published
0.1.0 release and keep preferences and kubeconfig unchanged.

Remove with `uv tool uninstall kuberich`, `pipx uninstall kuberich` or
`brew uninstall kuberich/tap/kuberich`. Preferences and kubeconfig remain intact.

## Known limits

This phase does not claim complete K9s parity. Owned kind clusters do not certify
EKS, AKS or GKE; real-provider trials remain opt-in
([#87](https://github.com/carloshm91/kuberich/issues/87)). Plugins run only from
files you configure; KubeRich does not download or update plugins. Mac archives
have ad-hoc signatures without Developer ID notarization.
