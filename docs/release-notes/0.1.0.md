# KubeRich 0.1.0

The first public release brings a Python terminal workspace for Kubernetes.
The [changelog](../../CHANGELOG.md) lists the individual changes.

## Features

- Browse live pods, namespaces, contexts, 15 standard resource views and discovered custom resources with typed sorting and stable selection.
- Complete `:` commands inline, filter with `/`, use Vim navigation and return through your previous views.
- Inspect redacted YAML, details and events, including optional managedFields.
- Press Enter on a pod for containers, then Enter for logs.
- Read current, previous or combined container logs with search, pause, follow, marks and plain-text or JSON exports.
- Keep up to 10,000 log lines within 4 MiB.
- Open container shells inside the workspace and browse 1,000 history rows with local search and redacted copy ([#123](https://github.com/carloshm91/kuberich/issues/123)).
- Confirm annotations, manifest dry-run/Apply, scale, restart, rollback, deletion and Job operations against the selected resource.
- Forward pod or Service ports, attach to containers and confirm uploads or downloads.
- Install Python packages or standalone Linux x86_64/ARM64 and macOS Intel/ARM64 archives ([#49](https://github.com/carloshm91/kuberich/issues/49)).

## Fixes

- Keep shell shutdown safe when history controls have already closed ([#51](https://github.com/carloshm91/kuberich/issues/51)).
- Change focus or themes without repeatedly rebuilding unchanged styles ([#150](https://github.com/carloshm91/kuberich/issues/150)).
- Keep real credential-helper errors distinct from successful macOS process cleanup ([#150](https://github.com/carloshm91/kuberich/issues/150)).
- Keep log navigation and resource selection stable during live updates.
- Cancel active requests and processes when leaving their view or context.

## Compatibility and migrations

- Python packages use CPython 3.12–3.14 on Linux or macOS.
- Standalone Linux archives require glibc 2.35 or newer.
- Standalone Mac archives require macOS 14 or newer; macOS 14 Intel remains untested.
- Use a UTF-8 terminal, trusted kubeconfig and permission to access your cluster.
- Install kubectl for shells, forwarding and transfers, plus any credential helpers declared in kubeconfig.
- Read-only mode blocks uploads and attach; downloads always need confirmation.
- Existing schema-1 development preferences remain readable; startup does not rewrite preferences or kubeconfig.
- Run preference migration explicitly when needed; this first public version has no earlier public release to upgrade from.

## Installation

Choose one Python installer for this version:

```sh
uv tool install --python 3.12 kuberich==0.1.0
# Alternative:
pipx install --python python3.12 kuberich==0.1.0
```

Use the [0.1.0 downloads](https://github.com/carloshm91/kuberich/releases/tag/v0.1.0)
for standalone archives and `DOWNLOAD-SHA256SUMS`. Keep the extracted directory
complete and check its checksum. Downloads also include dependency and source
reports.

Homebrew initially installs from source. For the current tap version, use
`brew install kuberich/tap/kuberich`; see [Install](../installation.md).

Start read-only, replacing these fictional names with your own. Select another
configuration file with `--kubeconfig /path/to/config` when needed:

```sh
kuberich --context sandbox --namespace demo --readonly
```

## Upgrade and uninstall

- Upgrade unpinned installations with `uv tool upgrade kuberich`, `pipx upgrade kuberich` or `brew upgrade kuberich/tap/kuberich`.
- Replace an explicit version constraint deliberately to move beyond that version.
- Replace standalone archives with a complete directory before removing the previous installation.
- Uninstall with `uv tool uninstall kuberich`, `pipx uninstall kuberich` or `brew uninstall kuberich/tap/kuberich`; preferences and kubeconfig stay intact.

## Known limits

- This version does not include metrics, user plugins or advanced node/debug operations.
- Real EKS, AKS and GKE cluster trials remain separate from local testing ([#87](https://github.com/carloshm91/kuberich/issues/87)).
- Mac archives use ad-hoc signatures and lack Developer ID notarization.
- Redaction recognizes documented credential patterns; it cannot identify arbitrary private application text.
- Terminal, font and clipboard combinations can behave differently; macOS 14 Intel remains untested.
