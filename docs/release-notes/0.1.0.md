# KubeRich 0.1.0

## Features

The first phase provides a Python/Textual Kubernetes workspace with live pods,
context and namespace tables, inline `:` completion, `/` filters, Vim navigation,
15 standard resource views and discovered custom resources. Inspect redacted
details/YAML/events, then open a pod's containers and their logs.

Single and aggregate logs provide bounded retention, search, pause/follow and
guarded export. Embedded kubectl shells preserve the workspace and provide
1,000 retained history rows, local Unicode search and explicit redacted
selection/copy ([#123](https://github.com/carloshm91/kuberich/issues/123)).

Guarded annotations, separate manifest dry-run/Apply, scale/restart/rollback,
UID/version-aware deletion, Job operations, port forwarding, captured attach
and file transfer retain explicit targets and read-only guards. Four standalone
archives accompany the Python packages
([#49](https://github.com/carloshm91/kuberich/issues/49)).

## Fixes

Reproducible dependency reports include the serial number required by GitHub's
SBOM attestation parser; identifiers cover the complete document and artifact
bindings without adding random build differences
([#89](https://github.com/carloshm91/kuberich/issues/89)).

Release validation separates its read-only branch-protection credential from the
job-scoped publication token, and reports missing owner configuration before
network/publication ([#89](https://github.com/carloshm91/kuberich/issues/89)).

Shell output tolerates footer removal during shutdown, while the owned PTY still
drains and reaps its child ([#51](https://github.com/carloshm91/kuberich/issues/51)).
Bounded renderer caches, incremental resource/log updates and parser/process
cancellation retain ownership and cleanup. Qualification preserves failing
originals and negative controls alongside corrected passing evidence.

Credential helper cleanup shares the owned-process signal guard: a transient
macOS teardown denial is accepted only after process-group removal is confirmed.
Real permission failures remain errors. Reader guides and generated references
describe product behavior without internal tracking codes
([#150](https://github.com/carloshm91/kuberich/issues/150)).

Reuse widget-owned component style nodes during focus and theme changes to reduce
temporary cyclic allocations, preserving native CSS evaluation and normal Python
garbage collection. Textual is pinned to the qualified framework version
([#150](https://github.com/carloshm91/kuberich/issues/150)).

## Compatibility and migrations

Source qualification covers Ubuntu 24.04 x86_64 and macOS 26 ARM on CPython
3.12–3.14. Standalone targets are Linux x86_64/ARM64 (glibc 2.35+) and macOS
Intel/ARM64 (measured macOS 14 floor). Native Mac trials use 14 ARM and 15 Intel;
physical macOS 14 Intel and broader source tuples remain unclaimed. Homebrew
source trials use Linux x86_64/macOS ARM/macOS Intel and Python 3.14.

An interactive UTF-8 terminal, trusted kubeconfig and permitted API access are
required. Shells, forwarding and transfers additionally need kubectl/RBAC;
declared cloud credential helpers remain external. Schema-1 development
preferences remain compatible. Launch does not rewrite preferences or kubeconfig;
explicit legacy preference migration remains a separate command.

This is the first public version, with no prior public upgrade baseline. Reviewed
0.x phases add capabilities; stable compatibility qualification remains 1.0 work.

## Installation

Version 0.1.0 is available from PyPI, the project Homebrew tap and
[GitHub Releases](https://github.com/carloshm91/kuberich/releases/tag/v0.1.0):

```sh
uv tool install --python 3.12 kuberich
# Alternative:
pipx install --python python3.12 kuberich
# Project organization tap:
brew install kuberich/tap/kuberich
```

GitHub Release assets include the four matching platform archives,
`DOWNLOAD-SHA256SUMS`, original audit/provenance records and these authored notes.
Verify the selected checksum and retain the complete extracted directory.
Homebrew initially builds from source; no bottle is promised.

Start with `kuberich --context YOUR_CONTEXT --namespace YOUR_NAMESPACE --readonly`.
Use actual permitted names and an explicit `--kubeconfig` when needed.
See the [installation guide](../installation.md).

## Upgrade and uninstall

Unpinned public installations use `uv tool upgrade kuberich`, `pipx upgrade kuberich`
or `brew upgrade kuberich/tap/kuberich`. Exact version/file constraints remain
effective and require deliberate replacement. First-version trials use immutable
owned baselines, normal upgrades and actual upgraded UI/shell behavior; they do
not invent an earlier public version. Subsequent public releases must qualify
the genuine supported predecessor.

Remove with `uv tool uninstall kuberich`, `pipx uninstall kuberich` or
`brew uninstall kuberich/tap/kuberich`. Preferences and kubeconfig remain intact.
Archive upgrades use a new verified complete directory; remove only the owned
old directory/symlink after successful replacement.

## Known limits

This phase does not claim complete K9s parity. Metrics, user plugins, advanced
node/debug operations and later phases remain pending. Owned helper/kind trials
do not certify EKS/AKS/GKE; real-provider trials remain opt-in
[#87](https://github.com/carloshm91/kuberich/issues/87). Physical terminal/font/
clipboard combinations and macOS 14 Intel have separate certification limits.
Mac archives have ad-hoc signatures, without Developer ID notarization.
Clipboard redaction recognizes documented credential patterns and bounded
selections; it does not identify arbitrary private application text.
Package and tap activation passed public-channel verification. Final website
and custom-domain activation remain separate owner-approved work.
