# KubeRich 0.3.0

See resource progress clearly, recover failed views and find focused task guides.
These notes describe the prepared source version; consult [Status](../first-preview.md)
for published availability and the [changelog](../../CHANGELOG.md) for individual changes.

## Features

- Browse large collections with visible INCOMPLETE counts and pagination progress ([#213](https://github.com/carloshm91/kuberich/issues/213)).
- Narrow API requests with `:server` selectors and choose compact metadata or full objects in generic views ([#213](https://github.com/carloshm91/kuberich/issues/213)).
- Retry one failed resource view while other views and port forwards keep working ([#216](https://github.com/carloshm91/kuberich/issues/216)).
- Create private, redacted diagnostic reports even when preferences are invalid ([#216](https://github.com/carloshm91/kuberich/issues/216)).
- Copy plaintext in local Wayland sessions with `wl-copy` and an explicit terminal fallback ([#220](https://github.com/carloshm91/kuberich/issues/220)).
- Authenticate with explicit Basic credentials, including an empty username or password half ([#215](https://github.com/carloshm91/kuberich/issues/215)).
- Generate an offline OIDC exec-migration fragment without copying tokens or changing kubeconfig ([#215](https://github.com/carloshm91/kuberich/issues/215)).
- Follow focused task guides with command, key and configuration references generated from the source ([#224](https://github.com/carloshm91/kuberich/issues/224)).

## Fixes

- Release memory for deleted resources during live updates ([#226](https://github.com/carloshm91/kuberich/issues/226)).
- Hide prepared Basic credentials in captured plugin output ([#215](https://github.com/carloshm91/kuberich/issues/215)).
- Restore your terminal after fatal UI errors and show a private crash-report path ([#216](https://github.com/carloshm91/kuberich/issues/216)).
- Navigate, resize and change themes without repeatedly updating unchanged headers ([#209](https://github.com/carloshm91/kuberich/issues/209)).
- Review custom-resource plugins using the selected API group, version and resource identity ([#278](https://github.com/carloshm91/kuberich/issues/278)).
- Read completed plugin-job output and exit status without pressing Enter again ([#272](https://github.com/carloshm91/kuberich/issues/272)).
- Load kubectl-compatible empty optional kubeconfig fields while preserving the selected credential scheme ([#215](https://github.com/carloshm91/kuberich/issues/215)).
- Migrate preferences explicitly while keeping old files; report success only when a new file is created ([#219](https://github.com/carloshm91/kuberich/issues/219)).

## Compatibility and migrations

- Source packages require CPython 3.12–3.14 on Linux or macOS; delegated operations still need their documented external tools.
- Existing 0.2.0 preferences load unchanged; no automatic preference or kubeconfig migration is required.
- Use `kuberich` instead of the warning-producing `kubetrol` alias; alias removal is planned for 0.4.0 ([#219](https://github.com/carloshm91/kuberich/issues/219)).
- Run `kuberich config migrate` only when you choose to create current preferences from older files; the originals remain intact.
- Legacy environment and log-file compatibility remain available; preference and kubeconfig writes still require an explicit action.

## Installation

A prepared source version does not make packages, archives or Homebrew bottles
available. Follow [Status](../first-preview.md) for verified published channels.
From this reviewed source checkout, with uv and CPython 3.12–3.14 installed:

```sh
uv sync --locked
uv run kuberich --version
```

Choose your context deliberately using the [quick start](../quickstart.md).
Public 0.3.0 installation commands require separate artifact qualification and
publication; these notes do not authorize or claim either.

## Upgrade and uninstall

- For a source preview, check out a reviewed newer revision and repeat `uv sync --locked`; retain its committed lockfile.
- Public `uv tool upgrade kuberich`, `pipx upgrade kuberich` and `brew upgrade kuberich/tap/kuberich` follow only versions activated on those channels.
- Replace an explicit version constraint deliberately before upgrading beyond it.
- Remove installed packages with `uv tool uninstall kuberich`, `pipx uninstall kuberich` or `brew uninstall kuberich/tap/kuberich`; preferences and kubeconfig remain intact.
- Removing a source checkout and its `.venv` does not remove your preferences or kubeconfig.

## Known limits

- Full 0.3.0 release qualification and channel activation remain separate from preparing this source version.
- Real EKS, AKS and GKE trials remain opt-in provider certification ([#87](https://github.com/carloshm91/kuberich/issues/87)).
- Mac archives retain ad-hoc signatures; Developer ID signing and notarization are not claimed.
- Startup and large collections can exceed development latency targets; full performance certification remains separate.
- Live usage metrics, ephemeral debug-container creation and complete K9s parity remain unavailable.
