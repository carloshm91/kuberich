# KubeRich 0.5.0

Prepare advanced operations for Helm releases, resource creation, Node maintenance,
debugging and bounded HTTP benchmarks. This source candidate is unpublished;
qualification and channel activation remain separate. The
[changelog](../../CHANGELOG.md) lists individual changes.

## Features

- Browse Helm releases, revisions and private values; review rollback with captured identity and explicit hook, wait and timeout options ([#66](https://github.com/carloshm91/kuberich/issues/66)).
- Manage chart catalogs and review Helm install, upgrade and uninstall with native server dry-run, live comparison and one-use confirmation ([#233](https://github.com/carloshm91/kuberich/issues/233)).
- Browse local manifests, render Kustomize and review guarded Apply/Delete batches with per-resource outcomes ([#67](https://github.com/carloshm91/kuberich/issues/67)).
- Create named resources from built-in/user templates, files or explicit clipboard/paste capture with strict dry-run and separate confirmation ([#234](https://github.com/carloshm91/kuberich/issues/234)).
- Open reviewed Linux node diagnostic sessions with UID-conditioned cleanup and explicit local recovery ([#76](https://github.com/carloshm91/kuberich/issues/76)).
- Cordon, drain and uncordon Nodes with disruption safeguards, separate data-loss consent and final scheduling observations ([#77](https://github.com/carloshm91/kuberich/issues/77)).
- Add ephemeral debug containers after review, inspect remote state and explicitly attach without implying remote completion from local closure ([#78](https://github.com/carloshm91/kuberich/issues/78)).
- Run confirmed, bounded HTTP benchmarks against one captured Service backend; browse private results without replay ([#79](https://github.com/carloshm91/kuberich/issues/79)).
- Explore admission policies, webhook declarations and scheduling constraints with typed tables and guarded object links ([#80](https://github.com/carloshm91/kuberich/issues/80)).

## Fixes

- Keep local plugin refusal messages visible while the current resource observation redraws ([#78](https://github.com/carloshm91/kuberich/issues/78)).
- Reveal matching relationship rows when delayed data replaces an empty filtered view ([#76](https://github.com/carloshm91/kuberich/issues/76)).

## Compatibility and migrations

- Python packages support CPython 3.12–3.14 on Linux or macOS; delegated operations retain their documented external-tool prerequisites.
- Existing 0.4 preferences, environment variables and logs remain compatible; loading settings never migrates configuration or kubeconfig automatically.
- Run `kuberich config migrate` explicitly when creating current preferences from legacy files; originals remain intact.
- The removed `kubetrol` alias does not return. Its separate 0.3 migration remains documented in the installation guide.
- Template schema 1 is data-only. User templates follow the selected configuration directory; capture stays offline until explicit review.
- Helm supports the reviewed 3.22.1/4.3.1 executables and Secrets or ConfigMaps release storage.

## Installation

Current published channels remain at 0.4.0 until separate approval and activation.
Once 0.5.0 is available, choose one Python installer:

```sh
uv tool install --python 3.12 kuberich==0.5.0
# Alternative:
pipx install --python python3.12 kuberich==0.5.0
```

After the project tap activates this version:

```sh
brew install kuberich/tap/kuberich
```

Standalone archives activate separately through
[GitHub Releases](https://github.com/carloshm91/kuberich/releases).
Follow [installation](../installation.md) for supported platforms, prerequisites
and checksum verification. Preparing this source does not publish any channel.

## Upgrade and uninstall

- For an unpinned 0.4 installation, use `uv tool upgrade kuberich` or `pipx upgrade kuberich` after 0.5 channel activation.
- Use `brew upgrade kuberich/tap/kuberich` after tap activation. Candidate qualification uses owned unpublished fixtures; public consumer verification follows activation.
- Pipx reinstall retains an original version pin; pipx upgrade can advance it. Replace the installation requirement deliberately to select an exact version.
- Pipx upgrades crossing from 0.3 still need the separate one-time reinstall that removes obsolete `kubetrol` links.
- Standalone upgrades replace the complete installation directory after checksum verification; keep preferences and kubeconfig outside that directory.
- Uninstall with `uv tool uninstall kuberich`, `pipx uninstall kuberich` or `brew uninstall kuberich/tap/kuberich`; preferences, logs and kubeconfig remain intact.

## Known limits

- Manifest batches and Helm operations are non-atomic; cancellation can leave uncertain or partial effects without automatic replay or compensation.
- Creation binds namespace names and reserves none; replacing a namespace between review and write remains a race.
- Trusted editors receive disclosed full drafts; sensitive template previews remain opaque, and private routing edits use public parameter/destination controls.
- Node diagnostics require explicit privilege. Disruption budgets or permissions can refuse maintenance; closing debug sessions never removes permanent declarations.
- HTTP load needs configured Vegeta and a reachable captured backend. Observation does not establish universal performance, effective policy or admission success.
- Real EKS, AKS and GKE certification remains opt-in ([#87](https://github.com/carloshm91/kuberich/issues/87)).
- macOS archives retain ad-hoc signatures; Developer ID signing, notarization and actual macOS 14 Intel execution remain unqualified.
- Startup/runtime latency targets remain advisory during 0.x; RSS, correctness, imports, frames, deadlines, coverage and cleanup remain hard gates.
- Windows and additional package channels remain future work. This prepared source publishes nothing.
