# KubeRich 0.4.0

Inspect cluster health, follow resource relationships and investigate workloads
with richer resource tables and private local reports. The
[changelog](../../CHANGELOG.md) lists individual changes.

## Features

- View current CPU/memory usage, requests, limits and labelled percentages in resource tables, with explicit missing or stale measurements ([#68](https://github.com/carloshm91/kuberich/issues/68)).
- Open `:pulse` for scoped resource health, source times and guarded resource drill-downs ([#69](https://github.com/carloshm91/kuberich/issues/69)).
- Follow owners, workload Pods, Service endpoints and Node placement through `:xray` ([#70](https://github.com/carloshm91/kuberich/issues/70)).
- Inspect supported configuration, storage and identity references with `:usedby`, including zero-replica workload templates ([#70](https://github.com/carloshm91/kuberich/issues/70)).
- Browse subjects, bindings, roles and aggregation with `:rbac`; inspect scoped authorization evidence using `:can-i`, `:rules` and `:who-can` ([#71](https://github.com/carloshm91/kuberich/issues/71)).
- Investigate scheduling, image pulls, crashes, readiness and volumes with `:diagnostics`; optionally run your configured Popeye executable ([#72](https://github.com/carloshm91/kuberich/issues/72)).
- Review and save redacted resource YAML, logs, diagnostics, screen text and support JSON; browse saved files through `:exports` ([#73](https://github.com/carloshm91/kuberich/issues/73)).
- Inspect container environment sources, precedence and image facts using `e`; values remain hidden until explicitly reviewed ([#74](https://github.com/carloshm91/kuberich/issues/74)).
- Open CPU, memory, network and filesystem metric history using Shift+M or `:history`, with ranges and explicit identity gaps ([#231](https://github.com/carloshm91/kuberich/issues/231)).
- Select Prometheus-compatible Services or independently configured HTTPS history backends without sharing Kubernetes credentials ([#231](https://github.com/carloshm91/kuberich/issues/231)).
- Browse 18 additional resource families with typed sorting, bounded details and captured resource links ([#232](https://github.com/carloshm91/kuberich/issues/232)).
- Filter warning Events, group occurrences by reason/object identity and open individual members through normal navigation history ([#232](https://github.com/carloshm91/kuberich/issues/232)).

## Fixes

- Prepare large export previews without constructing unused pages, and close log viewers without late updates targeting removed panels ([#317](https://github.com/carloshm91/kuberich/issues/317)).
- Preserve table scroll and explicit Home/End navigation across refreshes and pending viewport restoration ([#75](https://github.com/carloshm91/kuberich/issues/75)).
- Keep long context identities visible with truncation instead of clipping their entire header value ([#75](https://github.com/carloshm91/kuberich/issues/75)).

## Compatibility and migrations

- Python packages require CPython 3.12–3.14 on Linux or macOS. Delegated operations still require their documented external tools.
- Use `kuberich` for interactive sessions and scripts. This version removes the deprecated `kubetrol` console command and Python shim.
- Existing preferences, legacy environment variables and log locations remain supported; loading settings does not rewrite old files or kubeconfig.
- Run `kuberich config migrate` only when you choose to create current preferences from older files. The originals remain intact.
- Pipx users upgrading from 0.3 need the one-time reinstall described below to remove obsolete command links.

## Installation

After approved 0.4.0 publication, choose one Python installer on Linux or macOS:

```sh
uv tool install --python 3.12 kuberich==0.4.0
# Alternative:
pipx install --python python3.12 kuberich==0.4.0
```

Once the project tap activates this version:

```sh
brew install kuberich/tap/kuberich
```

Standalone downloads are activated separately through
[GitHub Releases](https://github.com/carloshm91/kuberich/releases).
See [installation](../installation.md) for platform prerequisites, checksums and
currently available channels. Source preparation does not publish these channels.

## Upgrade and uninstall

- Upgrade an unpinned uv installation with `uv tool upgrade kuberich`, or Homebrew with `brew upgrade kuberich/tap/kuberich` after channel activation.
- For an unpinned pipx installation crossing from 0.3, use `pipx reinstall kuberich`. Plain `pipx upgrade` can leave a dangling `kubetrol` link.
- Replace explicit version constraints deliberately; an installation pinned to 0.3 does not select 0.4 automatically.
- Uninstall with `uv tool uninstall kuberich`, `pipx uninstall kuberich` or `brew uninstall kuberich/tap/kuberich`. Preferences, logs and kubeconfig remain intact.

## Known limits

- Current usage needs an available metrics-server API; history needs an explicitly selected compatible backend. Missing data remains unavailable or unknown.
- Relationship and authorization views report observed scope and incomplete sources; they do not establish effective access for every identity.
- A zero-desired DaemonSet can remain unknown when Kubernetes omits optional health counters.
- Rapid horizontal key sequences can miss movement; Home/End and the object's Inspector remain available for complete field access.
- Real EKS, AKS and GKE certification remains opt-in ([#87](https://github.com/carloshm91/kuberich/issues/87)).
- Mac archives retain ad-hoc signatures; Developer ID signing and notarization are not claimed.
- Startup and large-collection latency targets remain advisory during 0.x; complete K9s parity and in-app Helm release management are not claimed.
